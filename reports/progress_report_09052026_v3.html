2Project context

Rare diseases collectively affect ~300 million people worldwide. Despite mature next-generation sequencing, ~50 % of exome/genome referrals remain undiagnosed. A substantial fraction of the gap is not undetectable variants but the limits of phenotype-driven prioritization tools (e.g., Exomiser) when the causal gene is novel, under-annotated, or only described in case reports / functional studies / phenotype-expansion papers — material that lives in unstructured literature.

This project asks whether a multi-agent RAG architecture deployed locally, grounded in pinned PMC OA literature, can meaningfully assist that synthesis step. The architecture decomposes the task across four specialized agents — Query Planner / Retriever / Critic / Synthesizer — coordinated as a stateful graph in LangGraph. The thesis evaluation isolates two contributions independently: (a) the multi-agent decomposition vs single-agent baseline, (b) hybrid dense + BM25 retrieval vs dense-only.

This work claims novelty in application, not in technique. RAG, multi-agent LLM systems, hybrid retrieval, and PMC corpora are all established. The contribution is the application of these techniques, in this combination, to rare-disease causal-gene prioritization, with rigorous reproducibility design and a 2×2+1 factorial evaluation against an external baseline (Exomiser).

3System architecture

Three implementation phases plus an evaluation phase. Phase 1A is the corpus-build substrate; Phase 1B is the test-case benchmark; Phase 2 is the agentic UI layer that the thesis defense demos.

Figure 1 — Phase 1A pipeline architecture, with measured demo runtimes annotated. Phase 1B and Phase 2 layer on top of this substrate.

Architectural principles

  1. Reproducibility-first. Identical inputs on the same hardware must yield byte-identical outputs. UUID5 chunk IDs, pinned PubMedBERT, pinned Qdrant image, dated ontologies SHA-256-hashed, RANDOM_SEED=42 everywhere, torch.use_deterministic_algorithms(warn_only=True).
  2. Hybrid retrieval native to the index. Dense PubMedBERT vectors capture semantics; Qdrant native BM25 sparse vectors capture exact gene/disease lexical matches. Fusion is reciprocal rank at query time. Hard rule: no hash-of-whitespace BM25 fallback.
  3. Local hardware sufficient. No cloud LLM. Important for reproducibility and any future extension to protected clinical data.
