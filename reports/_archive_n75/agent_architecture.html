1Research problem & rationale

Rare diseases affect ~300M people globally; ~50% of exome-sequencing referrals remain undiagnosed. The gap is most acute for novel/under-annotated causal genes whose phenotype-gene associations exist only in unstructured PubMed Central literature (>1M new articles per year, 4M+ in PMC OA alone). Hand-curation cannot keep pace.

The clinical question:

Given a patient's HPO phenotype profile and a list of 50 candidate genes from upstream variant calling, which gene is most plausibly causal — with citations?

Why a single-pass RAG fails this question

GapWhat's missing
No per-chunk relevance gradingSpurious retrievals contaminate the answer; no rejection of off-topic chunks
No iterative query refinementIf first retrieval misses, no recovery
No structured intermediate outputsClinician needs the reasoning chain, not just the final answer

The agentic decomposition

AgentSpecialist roleGap addressed
Query PlannerHPO graph reasoning + query constructionHand-crafts queries that exploit ontology structure
RetrieverHigh-recall hybrid searchDense + BM25 + RRF over PMC OA Qdrant index
CriticPer-chunk relevance gradingEach chunk gets a 1-5 grade with rationale
SynthesizerAggregation with explainable scoringPer-gene confidence in [0,1] with cited supporting chunks

2High-level architecture

Figure 1 — Four agents read & write a single shared AgentState. Sequential default flow; conditional self-correction edge from Critic back to Retriever (max 3 iterations). All four agents are pure-Python today; LangGraph orchestration + LLM swap-in pending C7.

The default sequential flow

INPUT → Query Planner → Retriever → Critic → Synthesizer → OUTPUT

Each agent is a Python function def node(state, *deps) -> AgentState that mutates the shared state. The orchestration layer (LangGraph in C7; today a pure function chain) routes between nodes and handles the conditional Critic→Retriever loop.

3Memory model

Single shared AgentState dataclass per case. No external memory store, no conversation buffer, no cross-case state. Every Phase 1B test case gets its own state object; nothing persists between cases.

Schema

@dataclass(slots=True)
class AgentState:
    case_id: str                                    # input
    hpo_terms: list[str]                            # input
    candidate_genes: list[str]                      # input

    expanded_hpo: list[str]                         # written by Planner
    mesh_queries: list[str]                         # written by Planner
    retrieved: dict[str, list[RetrievedChunk]]      # written by Retriever
    grades: dict[str, list[CriticGrade]]            # written by Critic
    ranked: list[GeneCandidate]                     # written by Synthesizer

    iteration: int                                  # loop control
    max_iterations: int = 3                         # loop control

Why no external memory store?

  1. Reproducibility. A run on a given case is fully determined by inputs + deterministic seeds + pinned models — no "previous conversation" lurking in a database.
  2. Per-case parallelism. The 75-case Phase 1B benchmark can run concurrently across processes without locking a shared store.

What is cached (process-scoped)

ResourceLoaderCache scope
HPO ontologysrc.tools.hpo.load_hpo@lru_cache(maxsize=2)
HGNC indexsrc.tools.hgnc.load_hgnc@lru_cache(maxsize=2)
PubMedBERT modelSentenceTransformer(...)per-instance
BM25 modelSparseTextEmbedding(...)per-instance

4Handoff protocol

Today: pure-Python state mutation

state = AgentState(case_id, hpo_terms, candidate_genes)
state = query_planner_node(state, hpo_ontology)
state = retriever_node(state, search_cfg)
state = critic_node(state, hpo_ontology, hgnc_index)
state = synthesizer_node(state)
# state.ranked now contains the final 50-gene ranking

No serialization. No message bus. Each function reads the fields its upstream wrote and writes the fields its downstream consumes. Direct dataclass mutation, type-safe end-to-end via mypy.

Tomorrow (C7): LangGraph wrapper

The same node functions become LangGraph nodes. LangGraph adds three things on top:

  1. Conditional routing between nodes (the Critic→Retriever loop).
  2. Partial-update merging: nodes can return only changed fields; LangGraph reduces them in.
  3. AG-UI streaming to the CopilotKit React frontend — each state mutation becomes an SSE event so the UI shows agent reasoning live.

The function-level interface (def node(state, ...) -> state) stays identical.

Why mutation rather than message passing?

  • Type-safe (mypy validates the shape end-to-end)
  • Zero-copy (no JSON encode/decode)
  • Inspectable (debugger sees the full state at any node boundary)

Trade-off: agents are tightly coupled to the AgentState schema. Mitigated by keeping it minimal and centralized in src/agents/state.py.

5Per-agent specification

1Query Planner

Transform input phenotype into ontology-broadened, gene-targeted query strings.

INPUT (read from state)
hpo_terms, candidate_genes
PROCESSING
1. Walk HPO parents (distance=2) for each term
2. Resolve to display labels (cap at top-5)
3. Build per-gene query: "{gene} {label1} {label2}..."
OUTPUT (written to state)
expanded_hpo[], mesh_queries[] (one per gene)
TOOLS
HPO ontology (pronto.Ontology)

2Retriever

Pull top-K most relevant chunks per gene from Qdrant.

INPUT (read from state)
candidate_genes, mesh_queries
PROCESSING
For each (gene, query):
1. Dense vector via SentenceTransformer.encode()
2. BM25 sparse via query_embed() (TF-only)
3. RRF fusion via Qdrant FusionQuery
OUTPUT (written to state)
retrieved{gene → list[RetrievedChunk]}
TOOLS
Qdrant + PubMedBERT (768d) + Qdrant native BM25

3Critic

Grade each retrieved chunk on three dimensions.

INPUT (read from state)
retrieved, expanded_hpo
PROCESSING (per chunk)
1. Gene mention? word-boundary regex over canonical + aliases
2. Relevance 1-5 from gene + HPO co-occurrence
3. Evidence type: case_report / functional / association / review / unknown
OUTPUT (written to state)
grades{gene → list[CriticGrade]}
TOOLS
HGNC index, HPO labels (read-only)

4Synthesizer

Aggregate grades into per-gene confidence + ranked output.

INPUT (read from state)
candidate_genes, grades
PROCESSING
contribution = relevance * evidence_w * mention_mult
score = sum(top-3) / 15.0 ∈ [0, 1]
Stable sort by descending confidence
OUTPUT (written to state)
ranked = list[GeneCandidate]
TOOLS
None — pure aggregation

Critic relevance scoring (1-5 ordinal)

ScoreCondition
5Gene + ≥2 HPO labels in 200-char co-occurrence window
4Gene + ≥1 HPO label (any distance)
3Gene mentioned, no HPO labels
2HPO labels present, no gene mention
1Neither

Synthesizer evidence weighting

Evidence typeWeight
case_report1.0
functional1.0
association0.8
review0.6
unknown0.5
no gene mention× 0.3 multiplier

6System orchestration

Conditional self-correction loop

Between Critic and Synthesizer, a conditional edge can route back to the Retriever:

def critic_routing(state: AgentState) -> Literal["retriever", "synthesizer"]:
    if state.remaining_iterations() > 0 \
       and state.n_low_confidence_grades() > 5:
        return "retriever"
    return "synthesizer"

State helpers used:

  • state.remaining_iterations() — clamps to 0; default budget = 3 loops
  • state.n_low_confidence_grades(threshold=2) — counts grades with relevance ≤ 2

Why this orchestration?

PropertyWhy
Linear defaultNatural information flow; can't grade what isn't retrieved
Self-correctionReal biomedical queries don't always retrieve right on first pass
Bounded loop (max 3)Prevents runaway iteration; deterministic execution time
Threshold of 5 low-confidenceHeuristic — tunable per evaluation cell

Justification — key choices

ChoiceWhy over alternatives
Dataclass state over Pydantic / TypedDict Pydantic adds runtime validation overhead + heavy dep. TypedDict can't carry helper methods. Slots dataclass = same ergonomics, zero deps, mypy-strict.
LangGraph over CrewAI / LangChain Agents / AutoGen State-graph-first: explicit nodes, edges, conditional routing. Others lean on prompted "free-form" agents — harder to evaluate quantitatively. LangGraph is also AG-UI's primary integration target.
Local Qwen3-8B over GPT-4 / Claude / cloud LLMs Reproducibility (pinned local model is byte-stable). Privacy (no patient data leaves the box). Cost ($0/call over many eval runs). Hardware fit (8B + KV + PubMedBERT + Qdrant fits 32 GB VRAM).
CopilotKit over custom React Ships chat UI + streaming + generative UI + HITL primitives out of the box. MIT-licensed self-hostable. Forked at Jangulo7/agent_UI.
Deterministic baseline first, then LLM swap-in 173 unit tests today exercise full agent contract without LLM/GPU/Qdrant. LLM responses are non-deterministic; baseline lets us separate "is orchestration correct?" from "is the LLM smart enough?" Baseline is also a valid cell in the §11.5 factorial.

8Why this answers the research challenge

The hypothesis: An agentic, multi-agent RAG architecture, deployed on local hardware and grounded in the published literature, can meaningfully assist literature evidence synthesis for rare-disease causal-gene prioritization.

What "meaningfully assist" requires architecturally

RequirementArchitecture delivers
Quantitative comparison vs ExomiserSynthesizer outputs aggregate_confidence ∈ [0,1] per gene → MRR / NDCG@K computable
Per-chunk evidence auditCritic emits CriticGrade per chunk with rationale string → UI shows why
CitationsGeneCandidate.supporting_chunks carries chunk_ids → trivial follow-back to PMC
Self-correctionCritic→Retriever conditional edge → recovery from poor first retrieval
Local deploymentSingle workstation, no cloud → reproducible by independent researchers
ReproducibilityPinned versions + UUID5 chunks + RANDOM_SEED=42 + MANIFEST.tsv hashes → byte-identical outputs
Quantitative evaluationDeterministic baseline + LLM variant: 4 of 5 cells are pure code, LLM is one swap-in

What multi-agent enables that single-agent cannot

  1. Per-chunk grading is empirically necessary. The §11.5 factorial directly tests this: multi-agent vs single-agent, with hypothesis that explicit per-chunk gating produces meaningfully higher top-K accuracy on long-tail rare-disease cases.
  2. Self-correction is empirically necessary. If first retrieval misses the causal evidence, the loop is the only mechanism for recovery without an external orchestrator.
  3. The agent decomposition is the explanation interface. A clinician can see: "Query Planner expanded HPO X → Y; Retriever returned 10 chunks for gene Z; Critic graded 3 at relevance 5; Synthesizer ranked Z first because of those 3 chunks." That narrative cannot be reconstructed from a single-pass system's output.

2×2+1 evaluation factorial (master plan §11.5)

Dense-onlyHybrid (dense + BM25 + RRF)
Single-agentCell A (control)Cell B (retrieval contribution)
Multi-agentCell C (architecture contribution)Cell D (full system)

Plus Cell E: Exomiser baseline (phenotype-driven, no literature). Metrics: top-1, top-5, top-10, MRR, NDCG@10 with paired-bootstrap 95% CIs over the 75 Phase 1B cases.

What this is NOT claiming

  • Not novel in technique. RAG, multi-agent systems, hybrid retrieval, PMC corpora are established. Contribution is application + reproducibility design + evaluation rigor.
  • Not a CE-marked clinical device. Research prototype.
  • Not a replacement for a clinician. Augments the hours of manual literature search.

10Roadmap to LLM-driven variant

Two LLM swap-in points

FunctionToday (deterministic)Tomorrow (Qwen3-8B prompted)
build_mesh_queries (Planner) Gene symbol + top-5 HPO labels concatenated LLM reasons about which HPO terms are most diagnostic; generates richer queries
grade_chunk (Critic) Regex-based relevance + section heuristics LLM reads (chunk + HPO + gene), returns structured CriticGrade

The Synthesizer remains pure aggregation — no compelling reason to put an LLM in clean math operations.

C7 implementation plan

  1. Install langgraph + vllm into pytorch-env
  2. Download Qwen3-8B weights to ~/rare-disease-rag/models/Qwen3-8B/
  3. Stand up vLLM in a Docker container alongside Qdrant
  4. Wire the four nodes into a langgraph.StateGraph with the conditional edge
  5. Add prompted variants of build_mesh_queries and grade_chunk
  6. Smoke-test the full graph against a Phase 1B case end-to-end

The deterministic chain stays as the always-available baseline (cells A/B in the §11.5 factorial). LLM variants evaluated against it to isolate the LLM's contribution.
