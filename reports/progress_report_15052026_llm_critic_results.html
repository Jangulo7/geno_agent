Headline — LLM-Critic effect is null on top-1

The LLM-prompted Critic, properly run with no fallback storm, does not improve top-1 over the deterministic Critic in either retrieval mode (G−C = −1.3 pp; H−D = −1.4 pp; both inside the 95 % bootstrap CI).

It re-orders chunks at top-5 / top-10 (G−C: top-5 +6.6 pp; H−D: top-10 +1.4 pp), but the gene at rank-1 does not change. The factorial decomposition cleanly points at retrieval as the bottleneck — leading to a Phase 2e proposal for a cross-encoder re-ranker.

Four contrasts isolate the LLM-Critic effect

G vs C — dense retrieval, LLM Critic added
−1.3 pp
top-1: 0.133 → 0.120 (within 95 % CI)

Top-1 regresses slightly. But at deeper ranks the LLM Critic helps: top-5 +6.6 pp, top-10 +4.0 pp, NDCG@10 +1.4 pp.

H vs D — hybrid retrieval, LLM Critic added
−1.4 pp
top-1: 0.627 → 0.613 (within 95 % CI)

Tied on top-5 (0.693) and MRR (0.670); top-10 +1.4 pp; NDCG@10 essentially unchanged (+0.2 pp). Hybrid retrieval saturates the Critic's headroom.

F vs D — hybrid retrieval, LLM Planner added (14/05)
−4.0 pp
top-1: 0.627 → 0.587 (LLM expansion dilutes BM25 anchor)

The LLM Planner's gene-aware reformulation has no headroom when BM25 already provides a strong lexical anchor. Adding the LLM Planner slightly hurts.

E vs C — dense retrieval, LLM Planner added (14/05)
+16.0 pp
top-1: 0.133 → 0.293 (LLM Planner substitutes for hybrid)

With no BM25 anchor, the LLM Planner's reformulation is the only thing supplying lexical signal. This is the one LLM-augmentation contrast where the LLM materially helps.

Why does the LLM Critic not move top-1?

The Critic operates on a fixed chunk set. It scores the top-K chunks the retriever surfaced and passes those scores to the Synthesiser. If the chunk that contains the actual causal evidence is not in the top-K retrieved set, no Critic at any model size can rescue the case.

Cell D's 0.627 top-1 reflects a retrieval ceiling: among the 75 cases, the truly causal chunk is in the top-10 retrieved set for ~63 % of cases when hybrid (BM25 + dense) retrieval is used, and ~13 % for dense-only. That ceiling is what the Critic-replacement experiments measure against — and the Critic, regardless of being rule-based or LLM-prompted, cannot exceed it.

The LLM Critic helps at top-5 / top-10 because that's where it has headroom. When the causal chunk is present in the top-10 retrieved set but ranked lower (position 3–5), the LLM's relevance grade can promote it past chunks that scored higher on pure lexical similarity. But for top-1 to change, the LLM must promote the causal chunk past a chunk that the retriever already ranked #1 — and the deterministic Critic's gene-mention + section-type heuristics are already strong enough to handle the unambiguous cases that dominate top-1.

What this means for the thesis

  1. Cell D (deterministic multi-agent + hybrid retrieval) is the operational winner. No LLM-augmented cell beats it on any metric.
  2. The LLM-Planner is a substitute for hybrid retrieval, not a complement. E − C = +16 pp on dense; F − D = −4 pp on hybrid. Useful where lexical retrieval is unavailable; not otherwise.
  3. The LLM-Critic is null on top-1 across both retrieval modes. It re-orders chunks at deeper ranks — useful for downstream evidence aggregation — but does not change rank-1. This justifies the deterministic Critic on operational grounds: ~50× faster (no GPU LLM call per chunk), reproducible bit-for-bit, and produces identical top-1 accuracy.
  4. The factorial decomposition is clean. Retrieval mode is the only main effect that meaningfully moves top-1; architecture (single vs multi) is a smaller contribution conditioned on hybrid retrieval; LLM augmentation has no main effect.

Phase 2e proposal — cross-encoder re-ranker

§11.5e Cross-encoder re-ranker between retrieval and critic proposed

Insert a cross-encoder re-ranking stage between retrieve and critic in the LangGraph. The factorial isolates retrieval as the binding constraint; this is the direct way to attack it. Stays inside the master plan: open-weight model, local inference, no cloud API.

Pipeline change

Current:    query → planner → retrieve(top_k=50) → critic → synth → top-N
Proposed:  query → planner → retrieve(top_k=50) → reranker(top_k=10) → critic → synth → top-N

Expected lift

Order-of-magnitude estimates from the IR literature on biomedical retrieval tasks (TREC-COVID, BioASQ, NFCorpus):

  • BM25 → BM25 + BGE-reranker-large: +5–15 pp top-1
  • Hybrid retrieval → hybrid + cross-encoder: +3–10 pp top-1

Applied to Cell D's 0.627 baseline: conservative +3 pp → top-1 ≈ 0.65; generous +10 pp → top-1 ≈ 0.73.

Open questions (resolved in Step 1)

  1. Where to truncate? Re-rank top-50 candidates → top-10 for the Critic. Top-100 → top-10 if compute allows; preserves more chance of surfacing deeply-ranked causal chunks.
  2. Per-gene or global? Per-gene first (preserves existing architecture); consider global pooling in a follow-up if per-gene fails to deliver.
  3. Score combination. Straight replacement of the second-stage score (the standard IR pattern). Don't introduce learned linear combinations until baseline lift is established.
