Difficulties & Solutions

D §6.1
Worker race condition in tarball extraction
Symptom: 40 worker crashes — "No such file or directory" on XMLs the worker had just extracted.
Root cause: All 12 workers extracted to the same /mnt/c/.../PMC<prefix>/ directory. Daily-incremental tarballs sharing a PMC ID raced, and --delete-extracted caused one worker's deletion to break another's parse.
Fix: tempfile.TemporaryDirectory() per-worker on Linux ext4. No two workers can ever share a path; auto-cleanup; ~10× faster than /mnt/c.
commit 8f0bc2a · PR #32
D §6.2
Atomic-write missing → 12 broken JSONLs survived as "already done"
Symptom: Normalize crashed with BadGzipFile after 50 files in.
Root cause: Parser used to write directly to the final .jsonl.gz path. SIGKILL'd workers left truncated gzips that passed the idempotency check (size > 0) and were skipped on rerun.
Fix: Write to .partial, atomic rename only on success. Normalize also wraps each input in a per-file try/except so a single bad file doesn't tank a 102-min pass.
commit 8f0bc2a · PR #32
D §6.3
Chunker OOM-killed at 62 GB RSS
Symptom: After 57 min and 16 M chunks produced, every worker hit BrokenPipeError; dmesg showed the kernel had OOM-killed the main Python process.
Root cause: pool.imap_unordered has an unbounded result queue. CPU-fast workers outran the slow /mnt/c gzip writer; the queue grew until 62 GB of un-consumed chunk lists tripped OOM.
Fix: Batched pool.map (default 2000 articles/batch — each batch fully drains before the next dispatches) + output moved to /home Linux ext4 (~10× faster than /mnt/c). Peak RSS in run #2: 9.6 GB.
commit d3b6d86 · PR #32
D §6.4
3 involuntary WSL/BIOS reboots in 24 h
Symptom: Saw BIOS screen 3 times on 2026-05-10. Each kill destroyed any in-flight tmux session.
Root cause: Host hardware — likely PSU marginality or thermal protection (RTX 5090 600 W TDP). Outside project scope.
Mitigation: Pivoted to NCBI FTP path on Windows side (immune to WSL reboots). Kept all subsequent WSL jobs ≤ 2 h. Recommend user check Windows Event Viewer for Kernel-Power 41 / WHEA-Logger.
External — no commit
D §6.5
Schema mismatch: FTP parser vs existing chunker
Symptom: Master-plan 08_section_aware_chunking.py expects pmcid, pub_year, mesh_terms, sections[].section_type. FTP parser emits pmc_id, pub_dates.epub, categories, raw section headings.
Fix: 03_normalize_dedupe_filter.py bridges the schemas in one pass that also does dedupe and genetics filter — three jobs, one pass.
commit 1121a60 · PR #32
D §6.6
Disk pressure on /mnt/c
Symptom: 5.76 M extracted XMLs filled /mnt/c from 848 GB free to 276 GB in 3 h; trajectory predicted disk-full within 80 min.
Fix: Killed in-flight chunker, renamed 14 PMC-prefix subdirs to _trash_subdirs/, background rm -rf, restarted chunker with output on /home (no /mnt/c writes for chunks at all).
Operational fix · no commit
D §6.7
WSL clock skew → cosmetic "negative elapsed" status lines
Symptom: Some mid-pipeline status messages showed elapsed time going backwards.
Root cause: Status thread uses time.time(); WSL2 re-syncs against Windows clock on certain events.
Impact: Cosmetic only — counters are in articles processed, not wall time. Future rewrites should use time.monotonic().
Known issue — low priority
